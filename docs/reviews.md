# Отзывы и рейтинг

После завершения заказа стороны оценивают друг друга. Схема собрана из
приёмов крупных площадок: двусторонние «слепые» отзывы (Airbnb, Upwork),
обязательное пояснение к низкой оценке (Profi.ru), публичный ответ на
отзыв (Avito, Google Maps), распределение оценок по звёздам (маркетплейсы).

## Как это работает

1. Заказчик принимает работу в чате. Заказ получает статус `completed` и
   дату завершения `completed_at`.
2. С этого момента у обеих сторон есть **14 дней**, чтобы оставить отзыв.
   Напоминание появляется:
   - в диалоге с собеседником, под панелью сделок;
   - в «Мои заказы» → «Оценить» (со счётчиком);
   - в меню профиля — «Оценить сотрудничество».
3. Отзыв — это оценка от 1 до 5 и текст. При оценке 1–2 текст обязателен
   (не короче 10 символов): низкую оценку нужно объяснить.
4. Отзыв **«слепой»**: пока вторая сторона не оценила, его не видит никто, и
   на рейтинг он не влияет. Второй стороне в чат приходит сообщение «вас
   оценили, оцените и вы».
5. Отзывы открываются **сразу, когда оценили оба**, или **через 14 дней**
   после завершения заказа. Второй случай обрабатывает таймер на сервере
   раз в час (`ReviewService.publishDue`).
6. Тот, о ком отзыв, может **один раз публично ответить**.

## Рейтинг

- В профиле два рейтинга: **как исполнителя** (`rating`, `reviews_count`)
  и **как заказчика** (`customer_rating`, `customer_reviews_count`).
  Хороший исполнитель и хороший заказчик — разные качества.
- Средние хранятся в профиле, а не считаются на каждый запрос: по ним
  сортируется каталог. Пересчёт идёт при каждой публикации отзывов
  (`ReviewService.recalculate`).
- Каталог сортируется по **байесовскому рейтингу** (`rating_score`):
  `(среднее × N + 4,5 × 3) / (N + 3)`. К настоящим оценкам «подмешиваются»
  три воображаемые оценки 4,5. Пример: у исполнителя 4,8★ по 4 отзывам
  балл 4,64, у новичка с одним отзывом 5★ — 4,63. Без этого один случайный
  отзыв на 5★ поднимал бы новичка выше проверенного мастера.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/reviews` | Оставить отзыв `{ orderId, rating, text }` |
| GET | `/reviews/pending` | Заказы, по которым можно оставить отзыв |
| POST | `/reviews/:id/reply` | Ответить на отзыв о себе |
| GET | `/reviews/user/:id?role=performer\|customer&page=` | Открытые отзывы о пользователе |
| GET | `/reviews/user/:id/summary` | Среднее, количество и распределение по ролям |

## Заодно

- Заказ, у которого уже есть исполнитель, больше нельзя удалить, только
  отправить в архив. На такой заказ ссылаются чат и отзывы, и после
  удаления история сделки сломалась бы.

## Спорные решения: нужно ваше решение

1. **Окно 14 дней и автопубликация через 14 дней.** После этого отзыв
   оставить уже нельзя. Плюс: нельзя дождаться чужого отзыва и «ответить»
   на него оценкой. Минус: кто не успел, тот не оценил. У Airbnb так же,
   у Avito окно больше.
2. **Отзывы нельзя редактировать и удалять** — ни автору, ни получателю.
   Так честнее, но опечатку тоже не исправить. Можно разрешить правку, пока
   отзыв ещё «слепой».
3. **Модерации и жалоб нет.** На реальной площадке нужна кнопка
   «Пожаловаться» и проверка оскорблений и контактов в тексте отзыва.
4. **Общая оценка без критериев.** Можно добавить «качество / сроки /
   общение», как на Profi и Kwork. Это точнее, но форма длиннее, а в
   отзывах реже пишут текст.
5. **Даже одна плохая оценка ставит исполнителя выше новичка без отзывов**
   (балл больше 0). Если это нежелательно, новичкам можно давать балл
   «по умолчанию», например 4,5.
6. **У старых завершённых заказов (до этой доработки) нет даты
   завершения**, поэтому по ним отзыв оставить нельзя. Для сида даты
   проставлены. Для настоящей базы можно разово проставить дату
   завершения по последнему сообщению в чате.
7. **Отзыв может оставить только участник сделки, прошедшей через
   площадку.** Отзывов «просто так» нет — это главная защита от накруток.
